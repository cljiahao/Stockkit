# Customer-Return Movement Reason Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `'return'` as a fifth `stock_movements.reason` value so a vendor can log a customer return as its own ledger entry instead of misusing `adjustment`.

**Architecture:** Widen the existing `reason` CHECK constraint via a new migration, extend the Zod schema and hand-maintained DB types to match, and add a `return` option to the stock-log form's reason picker as a positive-delta choice (like `restock`, but without the unit-cost field).

**Tech Stack:** Next.js 16 Server Components/Actions, Supabase Postgres (RLS unaffected — no policy change needed), Zod, Vitest + Testing Library (jsdom) for the UI test.

## Global Constraints

- TypeScript strict — no `any`, no `@ts-ignore`.
- Validate all user input with Zod at every boundary (`src/lib/schemas.ts`).
- `supabase/migrations/` and `src/lib/types.ts` must be updated together and stay in sync.
- Comment hygiene: own-line comments only, no trailing inline comments.
- `font-mono` stays on every quantity/cost figure — not touched by this change, but don't drop it if you touch adjacent JSX.
- No RLS/policy changes — `record_stock_movement`'s existing INSERT already accepts any value the CHECK constraint allows.

### Task 1: Widen the `reason` CHECK constraint

- Modify: `src/lib/types.ts:6`

**Interfaces:**

- [ ] **Step 1: Write the migration**

Create `supabase/migrations/0006_stock_movement_return_reason.sql`:

```sql
-- Add 'return' as a stock_movements reason: a customer returning an unused
-- item doesn't map to restock (implies bought from a supplier), adjustment
-- (implies correcting a count, not a real transaction), or waste/initial.
-- CHECK constraints can't be altered in place, so drop and recreate.
ALTER TABLE stockkit.stock_movements
  DROP CONSTRAINT stock_movements_reason_check;
ALTER TABLE stockkit.stock_movements
  ADD CONSTRAINT stock_movements_reason_check
  CHECK (reason IN ('restock', 'waste', 'adjustment', 'initial', 'return'));
```

The constraint name `stock_movements_reason_check` is Postgres's default
autogenerated name for an unnamed inline `CHECK` on the `reason` column
(`<table>_<column>_check`) — confirm it matches by running
`\d stockkit.stock_movements` against a live/local Supabase instance before
applying this in an environment where the name might differ (e.g. if a
prior migration ever renamed it — none currently does, per
`supabase/migrations/0001_initial_schema.sql:34`).
